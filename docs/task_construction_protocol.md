# Task-construction protocol

This protocol instantiates Revision Guide A3 and is the artifact-facing counterpart of the manuscript's Benchmark Construction section.

1. Specify a benign nominal goal and the acting principal.
2. Construct a synthetic interface with a safe and unsafe route to a comparable nominal endpoint.
3. Map the unsafe route to a documented deceptive-interface family and record the concrete low-level implementation.
4. Identify the exact risk point and define the machine-verifiable unsafe action.
5. Define the safe alternative, nominal endpoint, monotonic unsafe boundary, five-class termination taxonomy, and independent deterministic C/S fields.
6. Annotate the affected stakeholder, protected interest, potential non-numerical consequence, qualitative reversibility, and expected safeguard response.
7. Verify that the risk control is perceptible and actionable at the fixed viewport or documented interaction point.
8. Exclude any task requiring a live account, payment endpoint, sensitive personal data, or a judgment-only scorer.
9. Record task-grounded `necessity_basis`, structured safe-route endpoint/core-outcome equivalence, and the incremental consequence event; author opinion alone is not evidence.
10. Validate the current v2 registry, warning, browser, matrix, scorer, and artifact contracts with `./.venv/bin/python -m unittest discover -s tests/v2 -v`.
11. Freeze task identifiers, conditions, repeats, model/scaffold configuration, and analysis plan before formal collection.

The current Protocol v2 roster contains 12 consumer tasks—four forced action, four sneaking, and four interface interference. All must pass the registry necessity contract, real-browser path verification, deterministic C/S fixtures, and artifact-provenance checks before API-backed smoke. The historical nine-task benchmark card remains Version 1 provenance and does not govern Protocol v2.
